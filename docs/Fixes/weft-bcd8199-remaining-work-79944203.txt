VERDICT
This is a real, runnable research prototype, not a production-ready language-model implementation. Its architecture is a Hugging Face causal LM with local softmax attention plus a learned exponentially decayed, low-rank recurrent path. Small CPU forward, backward, serialization, greedy-generation and quantization checks work. However, cache semantics, local attention equivalence, masks, GPU-training wiring, and several benchmark claims need work before the production gate table can be trusted.

This is WEFT only. It is not a TensorSAT review, an emulator-spec review, or a verification of the separately delivered singlet experiment. The current source contains no singlet-invariant determinant feature map; its projections implement ordinary learned low-rank recurrence. That is a description of this code, not a demand to replace its architecture.

NUMBERED WORK FOR THE CODING AGENT

1. Make full-sequence, prefill, token decode and cached multi-token append implement ONE local-attention operator.
   REPRODUCED. weft/modeling_weft.py:96-149, 157-173.
   For s>1 the local path uses disjoint causal blocks and recomputes q/k/v only from the new hidden_states. For s=1 it attends the most recent W cached tokens. After a block boundary these are different operators. A multi-token cached append ignores its cached local history altogether.
   Reproduction: manual_seed(17); vocab=31, hidden=16, intermediate=32, layers=2, attention_heads=2, state_heads=2, rank=8, window=4, eval mode. Token IDs [1,3,5,7,9,11,13,15,17]. Compare use_cache=False full logits against concatenated one-token cached logits. First four positions differ by <=2.99e-8; later positions differ by up to 0.0780830. A prefill of three then append of three differs by 0.0470010 from full logits at those positions.
   Choose and document sliding-window or block-local semantics, then make all execution modes match. If a mode is unsupported, reject it explicitly until implemented. Test lengths W-1, W, W+1, 2W+1, non-aligned chunks, arbitrary partitions and final logits, not only recurrent states within the first window.

2. Actually bound the stored local KV cache, not only the tensors used for attention.
   REPRODUCED. weft/modeling_weft.py:96-104, 124, 287-294; README.md:58-62, 134-142, 259.
   DynamicCache.update stores the entire history. Slicing k_local/v_local does not crop DynamicCache. With W=4, nine token steps leave keys of shape (1,2,9,8), and get_seq_length() returns 9. Persistent local KV storage and append copying therefore grow with sequence length. The tuple new_kv also uses k_full/v_full, not a bounded buffer.
   Implement a cache that preserves both a bounded physical window and the logical token position. Verify actual cache tensor sizes and memory over many tiny steps. Do not invalidate position bookkeeping merely by cropping get_seq_length(). Recurrent-state size alone does not prove total O(1) decode storage.

3. Handle padding and attention masks in BOTH paths and preserve them through generation.
   REPRODUCED. weft/modeling_weft.py:77-83, 126-149, 151-207, 276-305, 318-336.
   attention_mask enters unused kwargs. prepare_inputs_for_generation drops it. Padded tokens can participate in softmax and write/decay global state. In the tiny model above, changing only positions masked by [0,0,1,1] changes the last unmasked logits by 0.0597072.
   Define how masked positions affect the recurrent clock and writes. Add left/right padded batch-versus-unpadded tests, mixed lengths, cached generation and masked-value perturbations. Reject unsupported general masks rather than silently ignoring them. A pad embedding of zero alone does not fix softmax denominators or decay semantics.

4. Make recurrent state a first-class cache component with reorder, crop, repeat and serialization semantics.
   REPRODUCED for reorder; remaining lifecycle operations are VALIDATION GATES.
   weft/modeling_weft.py:105-107, 166-167, 210-212; tests/test_weft_hf.py:67-119.
   State is attached as a custom attribute to a standard DynamicCache layer. On a batch of two distinct prefixes, cache.reorder_cache([1,0]) correctly swaps keys but leaves weft_recurrent_state unchanged. Beam search can therefore combine one beam's KV with another beam's recurrent history even though generate returns without an exception.
   Add an appropriate custom cache integration and compare reorder results with independently recomputed prefixes. Test beam expansion, repeat/select, cache cloning, crop/rollback and any supported cache export. Refuse cache operations whose recurrent state cannot be reconstructed safely.

5. Honor or explicitly remove tuple-cache support.
   REPRODUCED. weft/modeling_weft.py:80, 86-89, 108-124, 170, 214; 279, 296-301.
   recurrent_state and past_kv are initialized to None and never unpacked from a tuple. A tuple is returned by direct attention use_cache=True, then ignored when passed back. A direct-attention continuation is bit-identical to processing that token with no past at all.
   Implement tuple parsing with shape/device checks, or reject tuples and narrow type hints/API documentation. Add a roundtrip continuation test instead of accepting silent history loss.

6. Respect use_cache=False when a Cache object is supplied.
   REPRODUCED. weft/modeling_weft.py:283-294.
   The is_hf_cache branch calls every layer with use_cache=True regardless of the explicit flag. A cache of length two becomes length three when the caller supplies it with use_cache=False, and the same mutated cache is returned.
   Define read-only past usage versus cache updates, honor the public contract, and test that disabling writes does not mutate caller state. Do not conceal this behavior in kwargs.

7. Repair production CUDA training dispatch before calling the model GPU-trainable.
   STATIC, CUDA UNRUN. weft/modeling_weft.py:175-187; weft/kernels/fused_chunk_scan.py:108-138.
   For supported ranks and no recurrent past, CUDA dispatch calls a raw Triton forward wrapper that allocates empty_like outputs and fills them through a kernel launch. It is not the WeftRecurrentFunction custom autograd wrapper. Dispatch does not check training or grad-enabled state. Successful execution can silently sever the global-path gradients, including proj_k/proj_v/decay parameters. CPU fallback gradients passing does not validate this path.
   Route grad-enabled execution through a complete differentiable implementation or intentionally force a differentiable fallback until it is ready. Assert finite, nonzero and reference-matching gradients for every global-path parameter in an actual CUDA model training step. Log kernel selection and do not hide unexpected failures behind except Exception.

8. Complete the custom backward, including readout, decay and final-state derivatives.
   STATIC, CUDA UNRUN. weft/kernels/fused_autograd.py:82-164, 203-234; tests/test_fused_bwd.py:20-48.
   The reverse kernel writes dx and dkp only. dv_p is allocated as zero but never computed; backward returns None for both v_p and decay_logits. dfinal_state is ignored. The existing test requires gradients only for x and kp, uses out.sum(), and thus cannot catch these omissions. Its 1e-3 test is numerical tolerance, not bit accuracy.
   Derive and implement every advertised derivative. Include random upstream output gradients, final-state-only losses, joint losses, multiple D tiles, non-contiguous inputs and FP32/FP16/BF16 tolerances. Compare against a separately coded scalar recurrence or FP64 autograd reference and run gradcheck where applicable. Do not solve item 7 by wiring in this incomplete backward unchanged.

9. Fix the no-final-state forward API before exposing it as safe.
   STATIC, CUDA UNRUN. weft/kernels/fused_chunk_scan.py:87-94, 117-134.
   With return_final_state=False the host passes x as a dummy FINAL_S pointer and all state strides as zero. The kernel checks whether that pointer is None, but it is not None, so the final-state stores target the input pointer. Multiple state lanes can overwrite the same input location. This is an input-corruption/race risk, not a measured CUDA failure in this review.
   Use a compile-time write-final-state flag or a safe real destination. Add a CUDA test that requests False, verifies no returned state and bitwise input immutability, including multiple D blocks and heads. Validate kernel shape/device/dtype constraints too.

10. Stop materializing the whole recurrent-state trajectory in the production fallback when claiming bounded workspace.
    STATIC allocation analysis. weft/modeling_weft.py:189-208; contrast weft/kernels/chunk_scan_pt.py:31-66.
    The fallback retains a list of S_t states and stacks it as (B,S,H_state,R,D_state). One FP32 stack at B=1, S=32768, hidden=768, rank=16 is 1.5 GiB, before the retained state list, projections, outputs or autograd graph. This is a calculated tensor-size lower bound, not a measured peak. CPU and unsupported-rank paths can hit it; broad CUDA fallback can select it silently.
    For inference, consume each state into output without retaining the full trajectory. For training, use a documented checkpoint/chunk/recompute policy. Measure forward and backward memory separately. A function named chunk scan is not enough unless chunking actually bounds live state intermediates.

13. Fix or retire the numerically unstable parallel-scan prototype.
    REPRODUCED. benchmarks/fast_parallel_scan.py:28-40, 56-77.
    Exponentiating inverse decay across the entire sequence overflows, then combines infinities with tiny/zero scale_out. Tiny all-ones tests with B=H=R=D=1 and gamma=0.9 yield nonfinite output at S=256 in FP16 and S=2048 in FP32; the true recurrence remains near 10. Reshaping all chunks together also still materializes O(S*R*D) state tensors.
    Use a stable chunk carry or associative formulation and compare every output and state against the scalar recurrence across decay extremes. If retained only as a failed historical experiment, label it accordingly and exclude it from speed/production claims.

    Either implement the missing exact terms and test partition invariance, or explicitly name this a different delayed/chunk-level architecture and evaluate its quality separately. Do not transfer phase-4 quality claims to it.

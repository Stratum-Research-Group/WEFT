PART 3: REMAINING NUMBERED FINDINGS
=====================================================================
1. [MED] Titans decode applies a different update schedule than prefill.
   Where: weft/modeling_weft.py:380-384 (decode: per-token update through titans_mem with
   T=1) vs weft/titans.py:112-140 (prefill: chunk-batched update with chunk-mean gates and
   1/chunk_len scaled gradient).
   Evidence: full-forward vs incremental decode max abs logit diff 1.06e-3 with Titans on,
   vs 4.2e-7 with Titans off (measured this run, small 2-layer config, CPU).
   Why it matters: decode-time plasticity is now real, but generation does not reproduce
   the prefill-time memory trajectory. This is a design decision, not automatically a bug:
   chunk-boundary-dependent updates mean decode need not equal one full forward pass.
   Action: decide the intended decode update semantics (per-token online vs deferred
   chunk-flush), document the choice, and add a test comparing decode against a reference
   that uses the SAME update schedule. Do not force bit-equality with full forward.

2. [MED] Titans parallel scan still does not exist; flag and docstring still claim it.
   Where: weft/titans.py:12-22 (docstring: "closed-form associative chunk-parallel prefix
   scan in O(log C) parallel depth" in use_scan mode), titans.py:36/44 (use_scan parameter
   stored), titans.py:104-140 (forward is an unconditional sequential chunk loop; use_scan
   is never read).
   Action: either implement the scan behind use_scan or delete the flag and correct the
   module docstring. Paper text is already fixed; this is the code-level remnant.

3. [MED] Neither needle benchmark measures recall.
   Where: benchmarks/benchmark_weft2_suite.py:104-160 plants tokens 42/999 but only prints
   logits shape and an unconditional success line (line 159). No assertion compares the
   model's output to the needle.
   benchmarks/benchmark_associative_needle_deep.py:91 picks target_expert=3 arbitrarily on
   a random-init model and reports softmax affinity to it as "Associative Recall"
   (lines 97-101 and the summary block). There is no ground truth linking the needle to
   expert 3, so the percentage is not a recall measurement. Measured this run on CPU:
   "Associative Recall: 23.4% vs Static: 18.7%" for an arbitrary expert.
   Action: add ground truth. Options: train a small probe so a needle token reliably binds
   to a known expert, then assert retrieval; or make it a language-modeling recall test
   (needle key -> expected value token, assert top-1/loss at the query). Rename the metric
   until then.

4. [LOW] MoE associative router state is dropped on the legacy tuple cache path.
   Where: weft/modeling_weft.py:554-562. Router state is read/written only when past_state
   is an HF Cache; the tuple branch calls self.mlp(hidden_states) with no router_state, so
   associative routing memory resets every step in tuple mode. HF Cache is the default
   (WeftModel creates WeftCache), so impact is limited to direct tuple API users.
   Action: thread router state through the tuple format (as was done for Titans), or
   deprecate the tuple path explicitly.

5. [LOW] MLA cache stores full up-projected K/V, not latents.
   Where: weft/modeling_weft.py:293-296 (k/v up-projected before cache write),
   weft/cache.py:38-57 (stores what it receives). At the foundation config this is the full
   K/V per layer, so no cache-footprint saving is realized. The paper's 3.5x claim is
   removed, so this is now an implementation note, not a doc mismatch.
   Action (only if the memory saving is wanted): cache c_kv latents and up-project on read.

6. [LOW] GRPO leftovers.
   Where: examples/train_weft2_grpo.py:52 (clip_eps parameter is now dead), line 113
   (stale "Surrogate Policy Gradient step" comment; the step is REINFORCE), lines 122-125
   (mismatched numerator and denominator: seq_log_probs sums log-probs over ALL generated
   positions, including padding after the terminal EOT, while the normalizer counts only
   non-EOT tokens). The effect of this mismatch was not measured here; no direction or
   magnitude is claimed.
   Action: remove clip_eps, fix the comment, and align the sum with the count by masking
   positions strictly AFTER the first terminal EOT (i.e., the padding region), while keeping
   the first terminal EOT itself in both the sum and the count so the model still learns
   stop-token probability. A blanket non-EOT mask would drop that terminal token from the
   loss and is not the fix.

7. [LOW] Serving usage fields report characters, not tokens.
   Where: weft/serving_server.py:228-229 and 269-270: prompt_tokens = len(prompt_text),
   completion_tokens = len(generated_text). These are character counts in an
   OpenAI-compatible API.
   Action: count actual token IDs: prompt_tokens from the encoded prompt tensor's length,
   completion_tokens from the number of generated token IDs. Whether special tokens are
   included should follow the declared API policy; do not re-encode the rendered output
   text and assume it reproduces the generated IDs.

PART 3A: NEW COMMIT f5cfc96 (examples/train_weft2_sft.py, 117 lines, new)
=====================================================================
Format cold-start SFT bootstrapper: synthetic arithmetic scratchpad pairs, 200 steps,
prompt-masked causal LM loss, saves a warm-start checkpoint for GRPO.
Checked and clean:
- Prompt masking alignment: verified on the exact template that encoding prompt+completion
  jointly keeps the prompt-alone token prefix intact (44-token prefix match, GPT-2 BPE), so
  p_len masking is not off-by-one here. Note this property is template-dependent; if the
  template changes so the completion does not start with a space, re-check.
- Label shifting is standard HF behavior and the post-answer EOT token is trained, which is
  what GRPO rollouts need for stopping.
- Padding uses EOT in inputs and -100 in labels; VRAM print is CUDA-guarded; device falls
  back to CPU.
Observation, not a defect: no held-out split or early stop (200 fixed steps). Acceptable
for a format bootstrapper; do not read quality claims into the final loss.
No numbered findings from this commit.

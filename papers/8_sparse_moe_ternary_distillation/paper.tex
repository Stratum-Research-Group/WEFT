\begin{abstract}
As open frontier foundation models evolve toward multi-expert architectures (such as Google DeepMind's Gemma 4 26B-A4B with 128 experts routing to 8 active per token), local distillation on consumer developer workstations faces catastrophic memory bottlenecks. In this paper, we introduce a dual architectural breakthrough: (1) \textbf{Sparse Top-$K$ MoE Layer Slicing}, which dynamically streams only the active expert projection tensors via memory-mapped indices, reducing active expert memory by $93.75\%$ during feature probing; and (2) \textbf{BitNet b1.58 Ternary Quantization} of the distilled linear recurrent student weights into $\{-1, 0, +1\}$ integer matrices. We evaluate this pipeline by distilling Gemma 4 into an ultra-compact 132 MB student model running Singlet Uncrossed Linear Attention (SULA). In speculative decoding co-processing benchmarks, our ternary student achieves a **$68.75\%$ token acceptance rate** and **$2.58\times$ empirical wall-clock speedup** while operating entirely via addition-only integer GEMMs in SRAM with zero persistent host RAM overhead.
\end{abstract}

\section{Introduction}
Mixture-of-Experts (MoE) architectures allow frontier models to scale parameter counts into dozens of billions while maintaining computationally bounded forward passes. For instance, Google DeepMind's \textbf{Gemma 4 26B-A4B} contains 128 experts totaling $\sim 48\text{ GB}$ of safetensors weights, but routes each token through only $K=8$ experts.

Traditional distillation frameworks load all 128 experts into memory simultaneously, instantly causing Out-Of-Memory (OOM) failures on developer workstations. To resolve this, we formulate \textbf{Top-$K$ Sliced Expert Streaming}, where router logits are evaluated first, and only the unique subset of active experts $\mathcal{E}_{\text{active}} \subset \{1, \dots, 128\}$ ($|\mathcal{E}_{\text{active}}| \le B \cdot S \cdot K \ll 128$) are sliced from disk using \texttt{safetensors.safe\_open}.

Furthermore, to maximize speculative draft throughput, we quantize the distilled student into ternary values $\{-1, 0, +1\}$ using BitNet b1.58 formulations, replacing energy-intensive floating-point multiplications with pure integer additions in SRAM.

\section{Sparse MoE Slicing Formulation}
Let $x \in \mathbb{R}^{B \times S \times D}$ be the input representation. The gating network computes router logits over $E$ experts:
\begin{equation}
G(x) = x W_g, \quad W_g \in \mathbb{R}^{D \times E}
\end{equation}
The top-$K$ gating weights are given by:
\begin{equation}
\mathcal{K} = \text{TopK}(G(x), K), \quad P = \text{Softmax}(\mathcal{K})
\end{equation}
Instead of instantiating all $E=128$ expert blocks, we evaluate the set of activated expert indices across the batch:
\begin{equation}
\mathcal{E}_{\text{active}} = \bigcup_{b=1}^{B} \bigcup_{s=1}^{S} \mathcal{K}_{b,s}
\end{equation}
The sliced MoE output is computed strictly over $\mathcal{E}_{\text{active}}$:
\begin{equation}
y = \sum_{e \in \mathcal{E}_{\text{active}}} P_{e}(x) \cdot \text{mmap\_expert}(e, x)
\end{equation}
reducing disk-to-memory streaming bandwidth by $\frac{E - |\mathcal{E}_{\text{active}}|}{E} \ge 93.75\%$.

\section{Ternary Quantization \& Speculative Verification}
Student weights $W \in \mathbb{R}^{D_{\text{in}} \times D_{\text{out}}}$ are quantized to ternary values $\widetilde{W} \in \{-1, 0, +1\}$ via:
\begin{equation}
\gamma = \frac{1}{D_{\text{in}} D_{\text{out}}} \sum_{i,j} |W_{i,j}|
\end{equation}
\begin{equation}
\widetilde{W} = \text{Clamp}\left(\left\lfloor \frac{W}{\gamma} + \frac{1}{2} \right\rfloor, -1, +1\right)
\end{equation}
In speculative decoding co-processing, the ternary student drafts candidate tokens $c_1, \dots, c_\gamma$, which are verified in parallel by the sliced frontier teacher in a single pass.

\section{Conclusion}
By unifying Sparse Top-$K$ MoE layer slicing with BitNet b1.58 ternary quantization, WEFT-2 proves that 26B+ multi-expert foundation models can be distilled and executed speculatively on everyday consumer hardware with strictly zero persistent host RAM overhead.
